# Spikes before M2 (2026-11-06)

Answers to SPEC.md §10 questions 2 and 3, found read-only: Plymouth and Plasma
sources (sources.debian.org; freedesktop's GitLab blocks automated reads), the
installed binaries and scripts, and measurements whose files stayed in `.dev/spike/`.
Plymouth source: Debian's 24.004.60; Ubuntu ships a git snapshot of 2025-08-31 on top
of it, and every key below was confirmed with `strings` in the installed `.so` files.

## two-step: hiding messages

`SuppressMessages=true` in a mode section (`[boot-up]`, `[shutdown]`, `[reboot]`, …)
makes `show_message()` drop status messages (`plugins/splash/two-step/plugin.c`,
`load_mode_settings`). Per mode, so boot can hide them while shutdown shows them.
No need for the script module.

## two-step: animation timing

- Everything redraws at 30 fps (`FRAMES_PER_SECOND 30`).
- The looping animation (`throbber-*.png`) always takes **2.0 s per loop**
  (`THROBBER_DURATION 2.0` in `ply-throbber.c`): the frame shown is
  `frames × (time in loop / 2.0 s)`. More than 60 frames are skipped, fewer are held.
- `animation-*.png` (end animation) plays each frame once at 30 fps;
  `progress-*.png` follows boot progress.
- All frames are decoded into memory when the splash starts.
- The script module redraws at 50 Hz by default, changeable with
  `Plymouth.SetRefreshRate()` (present in the installed `script.so`); the script
  picks the frame, so any loop length and frame rate works.

**Consequence for M2:** loops up to 2 s use two-step's throbber; longer loops, or
lower frame rates to save space, use the script module.

## Frame sizes against the 15 MB cap

120 frames (4 s at 30 fps), PNG (`-pred mixed`) and lossy 256-colour PNG
(`palettegen` + `paletteuse`, sierra2_4a dither). "s" = seconds that fit in 15 MB.

| Source | Size | Kind | KB/frame | s @30 fps | s @15 fps |
|---|---|---|---:|---:|---:|
| Overload (graphic on black) | 2560×1440 | PNG | 44 | 11.6 | 23.2 |
| | | 256 colours | 33 | 15.7 | 31.3 |
| | 1280×720 | 256 colours | 12 | 44 | 88 |
| | 512×288 | PNG | 3 | 149 | 299 |
| Mandelbrot zoom (detailed) | 2560×1440 | 256 colours | 1098 | 0.5 | 0.9 |
| | 1280×720 | 256 colours | 311 | 1.6 | 3.3 |
| | 512×288 | 256 colours | 59 | 8.7 | 17.4 |

Content matters far more than resolution. The second limit is memory: decoded
frames take width × height × 4 bytes (1440p: 14 MB per frame, 422 MB per second at
30 fps; 720p: 105 MB/s; 512×288: 17 MB/s), all loaded before the first frame, and
decoding costs ~11 ms per 1440p frame and ~3 ms per 720p frame (ffmpeg's decoder,
single thread; libpng is likely slower).

**Consequence for M2:** besides the 15 MB file cap, a decoded-memory budget of about
300 MB (a ~0.5–1 s delay before the splash shows). Within it: a 2 s full-screen 1440p
loop at 10 fps, ~3 s of 720p at 30 fps, or long 512×288 animations. The editor shows
both meters.

## MP4 start delay in a Plasma splash

A QML `MediaPlayer` + `VideoOutput` (QtMultimedia's ffmpeg backend, as `Splash.qml`
would use it), headless, 4 s 1440p H.264 (2.0 MB, CRF 20): first video frame ~32 ms
after `play()`, ~150–200 ms after process start including Qt, the QML engine and the
multimedia plugin. A PNG still of the same frame took ~47 ms to load.
Harness: `.dev/spike/mp4/` (not part of the repo).

**Consequence for M2:** MP4 through QtMultimedia works; the first-frame still from
SPEC §4.7 is optional, not needed to hide a gap.

## two-step's live text under dracut

Ubuntu's `plymouth-populate-initrd` (used by dracut's `45plymouth`) packs
`label-pango.so`, the Ubuntu font family, the fontconfig default and monospace
fonts, and the fonts named by `Font=`, `TitleFont=` and `MonospaceFont=`. It packs no
fontconfig configuration, but libfontconfig 2.17's built-in fallback scans
`/usr/share/fonts`, where those fonts land. So live text should render, and under
dracut `Font=` is honoured. Not yet seen on a dracut boot.

## Splash-only packages and Global Themes

Plasma's Global Themes page (`kcms/lookandfeel/kcm.cpp`, `loadModel()`) lists only
look-and-feel packages with `contents/defaults` or `contents/layouts`. A package with
just `metadata.json` and `contents/splash/` (Overload, Penrose, and what Ekpo
generates) never appears there, while the Splash Screen page still offers it. Checked
in plasma-workspace 6.7.4's source; this machine runs 6.6.6.
